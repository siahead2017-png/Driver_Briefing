# Спецификация: пересборка сценария инструктажа по записи 18.08.2026

## Задача

Владелец сам написал сценарий, сам его вёл дважды подряд (12.08 и 18.08) — и оба
раза съезжал в одни и те же перегрузы по времени, несмотря на то что после первой
записи в сценарий уже добавили заметки против этого. Заметки не сработали, потому
что лежат в `note` — визуально бледном, второстепенном тексте (13.5px, приглушённый
цвет), который легко проскочить взглядом на середине живого разговора с водителем.
Плюс: вступление и закрытие инструктажа выпали целиком, потому что часть этого
контента вообще не показывается во время разговора — живёт только в `guide`,
который читается один раз до первого инструктажа.

## Решение

1. **Ограничители по времени переезжают из `note` в основной видимый текст**
   (`text`/`checklist`) тех пунктов, где они уже проваливались дважды: калькулятор,
   боксы, EUROVIGNETTE, карты. Presenter физически не может их не заметить — они
   в жирном 15px-тексте, который и так читается вслух, а не в бледной строке под ним.
2. **Блок 5 «Красная линия» сливается в блок 3** — на практике оба раза разговор
   про заправку прицепа/датчики/чек шёл естественно внутри разговора про карты,
   а не отдельным блоком. Семь карточек становятся шестью.
3. **Блок 3 переименовывается в «Заправки и карты» и перестраивается как таблица**,
   сгруппированная по гео — «В Европе» / «В Латвии» — плюс отдельное предупреждение
   про CROSSCHEM (AdBlue), а не плоский список из 9 карт. Пользователь явно отменил
   решение от 12.08 «не перечислять карты по одной»: нюансы важны, но по каждой
   карте — одна строка, а не абзац.
4. **«Что сделать после» переезжает из `guide` в видимые пункты последнего блока** —
   с поправкой: фраза «после меня инструктаж отдела контроля» была фактически
   неверна (порядок иногда обратный), убрана; вместо неё — нейтральная просьба
   изучить базу знаний.
5. Тайминг блоков пересчитан под перегруппировку (6 тем вместо 7), но **не
   подтверждён вживую** — это сознательно вне этой сборки, см. «Вне рамок».

## Решения по реализации

- **Никаких новых полей схемы.** Используем существующие `text`, `checklist`,
  `table`, `note`, `critical`, `quote`, `link`/`links`, `href`. Причина: `note`
  как механизм не сломан — сломано было решение класть туда единственную защиту
  от растягивания; сама схема рендерит `note` нормально (`app.js:62`), просто
  визуально вторична (`styles.css` — 13.5px против 15px/550 у `text`).
- **Блок `b5-redline` удаляется, его пункты переезжают в конец `b3-cards`**
  (переименован в «Заправки и карты»), **с сохранением исходных `id` и порядка
  пунктов** — `red-video → red-separate-receipt → red-sensors → red-bribe →
  red-closing` идут последними четырьмя-пятью пунктами блока 3, сразу после
  карточных пунктов, без реордеринга внутри себя. `red-video` при переносе
  получает явный checklist вместо пересказа своими словами: `["Открыть видео
  заранее, до водителя", "Нажать play при водителе — showать, не рассказывать
  словами"]`. `red-closing` переносится без изменений — короткая цитата остаётся
  последним пунктом объединённого блока. `num` у блоков после четвёртого
  сдвигается на единицу (было 0–6, станет 0–5).
- **Карты: новая структура внутри блока 3** — вместо восьми отдельных `say`-пунктов
  по одной карте (`cards-main`, `cards-neste-pin`, `cards-crt`, …) — один пункт
  с `table`, две группы строк (Европа / Латвия), плюс отдельный пункт CROSSCHEM
  (AdBlue) вне таблицы, потому что у него не «где платить», а «ловушка с PIN» —
  разная форма информации, разная подача.
- **Конкретный видимый текст для трёх пунктов, где лимит раньше проваливался
  (не просто «лимит в text», а сам текст):**
  - `phone-calc` (блок 1): `text` → «Калькулятор — оранжевая кнопка. Открыть,
    назвать две вкладки, закрыть — не больше 40 секунд». Разбор полей и формул
    остаётся только в `note` как справка для самого ведущего, из читаемого вслух
    текста убран.
  - `tolls-boxes` (блок 2): в `checklist` добавляется строка «Как это устроено
    внутри — не объяснять. Одна фраза: где-то винетки, где-то шлагбаум, где-то
    спутник — а как рассчитано, неважно».
  - `tolls-eurovignette` (блок 2): в `checklist` добавляется строка «Шаги формы
    (их девять) вслух не перечислять — заполняется по ссылке самостоятельно».
- **Строка-предохранитель «чего там нет» у экрана «Запреты движения»**
  переезжает из `note` в `checklist` пункта `tolls-bans` (блок 2): «Чего тут
  НЕТ: городских экозон, тоннелей, перевалов, весенних ограничений по осям —
  только общенациональные запреты» становится отдельной строкой чеклиста, а не
  фразой в конце note. В блоке 1 (`kb-tour`) плитка «Запреты движения» получает
  явную пометку в тексте: «коротко — подробно в блоке 2», чтобы не разворачивать
  тип груза и даты уже здесь.
- **Блок 0 «Рамка» помечается `critical: true`** на пункте `frame-opening» —
  единственный способ в существующей схеме сделать пункт визуально
  неигнорируемым (та же красная рамка, что у денежных пунктов). Причина, почему
  он пропускается целиком, — не текст, а спешка в начале разговора; полностью
  исключить пропуск редактированием JSON нельзя, но красная рамка — та же мера,
  что уже работает для денежных пунктов, применяется здесь впервые к
  «пропускаемому», а не только к «дорогому».
- **«Что сделать после»** дублируется, не переносится: `guide.sections` держит
  версию для однократного чтения перед первым инструктажем (с чуть большим
  контекстом «зачем»); блок 5 (бывший 6) получает сжатую видимую версию —
  **три конкретных say-пункта**, а не общая фраза: (1) «Отдать памятку — один
  лист», (2) «Если что-то не установлено (приложение, иконка) — отметить и
  сообщить в отдел учёта», (3) «Напомнить про «Написать в офис», если в рейсе
  что-то сломалось — не ждать возврата на базу». Пункт про «дальше инструктаж
  отдела контроля» исключается по ответу пользователя (G02) и не заменяется
  ничем конкретным — только общее «изучите базу знаний» отдельной строкой.
- **Открывающая цитата блока 0** (`frame-opening`) правится: убрать «После меня
  у вас будет ещё инструктаж с отделом контроля» (не всегда верно — порядок
  бывает обратный), заменить на нейтральное продолжение про самостоятельное
  прохождение вводного инструктажа, без утверждений о порядке дальнейших шагов.
- **Блок 4 «Банковская карта» содержимого не меняет.** Правило «согласовывать
  парковку/тоннель заранее и письменно, указывать имя менеджера» (`bank-preapprove`)
  уже существует в сценарии с 12.08 и не было проблемой контента — 18.08 до него
  просто не дошли по времени, потому что предыдущие блоки растянулись. Весь смысл
  §1–3 этого документа — не дать этому повториться, поэтому отдельного решения
  для блока 4 не требуется; он остаётся контрольной точкой приёмки (см. «Покрытие
  манифеста»).
- **`minutes` у блоков** пересчитываются по перегруппировке (эвристика, не замер):
  b0=2, b1=7, b2=6, b3=8 (было 6+3=9, минус ~1 за счёт снятия дублирующих
  переходов между блоками), b4=4, b5=3. Итого 30.

## Границы и швы

Один файл данных (`data/briefing.json`), один владелец, один проход — границы
модулей не заводятся: изменения внутри существующей JSON-схемы, рендерящий код
(`assets/js/app.js`, `assets/js/util.js`) не меняется. Шов для проверки —
`tools/validate.py` (структура и битые ссылки) плюс визуальная проверка через
`serve.ps1`, что блоки 0–5 рендерятся и ничего не потерялось при переносе id.
