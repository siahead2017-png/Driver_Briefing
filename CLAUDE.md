# Контекст проекта

Инструмент для проведения инструктажа водителя: шесть тем плюс вступительная
«Рамка» (блок с `num: 0`), тайминг на 30 минут, отметки о пройденном.
Открывается с телефона.
Это инструмент **для ведущего** (отдел учёта), а не справочник для водителя —
водителю на руки идёт памятка из `dist/`.

**Инструктаж ведёт не только владелец, но и его коллеги** (решено 02.08.2026).
Отсюда два следствия, которые легко нарушить: в сценарии не должно быть личных
имён (для подстановки есть слоты `{имя}` / `{должность}`), а логика «почему
такой порядок, что значат цвета» должна жить в разделе `guide`, а не в голове
у автора.

Боевой адрес: https://siahead2017-png.github.io/Driver_Briefing/

**Язык общения с пользователем — русский.** Интерфейс тоже только русский.

## Место в семье проектов

Три связанных сайта одного владельца, общая дизайн-система:

| Проект | Для кого | Адрес |
|---|---|---|
| `Driver_Instructions` | водителю — база знаний, 64 карточки, видео, калькулятор | siahead2017-png.github.io/Driver_Instructions/ |
| `FuelInstruction` | водителю — где и какой картой заправляться, цены обновляются ежедневно | siahead2017-png.github.io/FuelInstruction/ |
| `Driver_Briefing` | ведущему — этот проект | siahead2017-png.github.io/Driver_Briefing/ |

Локально база знаний лежит в соседней папке `../Dashboard_Instructions` (имя папки
и имя репозитория расходятся — так исторически). `tools/validate.py` проверяет по ней
ссылки; если папки нет, проверка мягко пропускается.

**У базы знаний есть два «виртуальных экрана», и ссылки на них устроены иначе.**
`#/bans` («Запреты движения», 23 страны) и `#/feedback` («Написать в офис» —
вопрос, заявка на ремонт, пожелание, жалоба, предложение) — не карточки, а
собственные экраны приложения. Поэтому в `briefing.json` они подключены через
`href` с полным адресом, а не через `link` + `kbBase`: `kbBase` дописывает
`#/item/`, и ссылка привела бы в никуда. По той же причине `validate.py` их не
проверяет — открывать руками. Оба экрана в бою (сверено с `git status` соседнего
репозитория 12.08.2026).

## Главное правило

**Никакой сборки и никаких зависимостей в самом сайте.** Чистые HTML/CSS/JS (ES-модули).

Причины те же, что и в соседних проектах: GitHub Pages отдаёт файлы как есть,
владелец правит контент через веб-редактор GitHub не открывая терминал, проект
не должен протухнуть через год без обновлений npm. Плюс он переносится между
домашним и рабочим компьютером, состав софта на котором заранее неизвестен.

**Не предлагать** React, Vite, Tailwind, бандлеры, npm-пакеты в рантайме.

Node и Python используются **только как инструменты разработки** — генерация PDF,
QR и иконок. Их результаты коммитятся, поэтому на машине без Node/Python сайт
полностью работоспособен; недоступна только пересборка.

## Окружение (важно)

Node.js и Python (через `py`) есть. `playwright`/`pypdf`/`segno` для сборки PDF и QR
ставятся по `tools/requirements.txt` (`py -m pip install -r tools/requirements.txt`
+ `py -m playwright install chromium`) — не предустановлены по умолчанию, проверять
перед первым запуском `build_pdf.py`/`make_qr.py` на новой машине.

**Грабля: `python` — это заглушка Windows Store** (`WindowsApps\python.exe`), она
молча ничего не делает и выводит пустую строку вместо версии. Настоящий интерпретатор —
**только `py`** (`...\Programs\Python\Python312\python.exe`). Все команды в документации
и все инструкции пользователю писать через `py`.

Вывод кириллицы в консоль ломается на cp866 — запускать скрипты как `py -X utf8 tools/….py`,
иначе в выводе будет каша (на сам результат работы это не влияет).

**Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI** — кириллица в скриптах ломает
парсер. `serve.ps1` держим **ASCII-only**. На этом уже падал такой же файл в соседнем проекте.

Локальный сервер обязателен: страница читает JSON через `fetch()`, из `file://` запрещено.

**Останавливая `serve.ps1`, не убивать процесс по владельцу порта** — `Get-NetTCPConnection`
покажет PID 4 (System), потому что префикс регистрируется в HTTP.sys ядра. Искать нужно
процесс `powershell.exe` с `-File …serve.ps1` в командной строке. И осторожно с фильтром
по `CommandLine`: слишком широкий шаблон совпадёт с самой командой поиска, и она убьёт себя.

## Модель данных

Всё содержимое — `data/briefing.json`. Четыре независимых раздела:

- `blocks[]` — сценарий для ведущего. Блок → `items[]`, у пункта обязательны
  `id`, `level` (`say`/`show`/`skip`), `text`; остальное необязательно.
- `guide` — «Как вести инструктаж», онбординг для коллеги. **Верхнего уровня,
  не элемент `blocks[]`** — иначе попал бы в счётчик пунктов, прогресс-бар,
  сумму минут и печатный сценарий.
- `cheatsheet` — памятка водителю. **Отдельный текст, не выводится из `blocks`:**
  у неё другой адресат, поэтому обращение на «ты» и другие формулировки.
  Дублирование здесь осознанное.
- `contacts` — контакты офиса, тоже уходит водителю (PDF по QR-коду). **PDF собирается
  здесь (`office-contacts.pdf`), но живёт на сайте `Driver_Instructions`**, не здесь:
  `build_pdf.py` копирует его в `../Dashboard_Instructions/assets/docs/` (мягко, если
  папка есть), а `links.contacts` в этом JSON указывает на `Driver_Instructions`.
  Причина: при сканировании QR телефон показывает домен из ссылки до открытия —
  «Driver_Briefing» ничего не скажет водителю (внутренний инструмент ведущего),
  а «Driver_Instructions» он уже знает как приложение «Инструкции».

`link` / `links[].id` — идентификаторы карточек базы знаний, URL собирается из `kbBase`.

**Слоты `{…}`** в `text` и `quote` — места, которые ведущий подставляет голосом
(имя, должность). Рендерятся синим пунктиром через `slots()` в `assets/js/util.js`;
экранирование идёт ДО подстановки `<span>`, поэтому инъекция невозможна.

## Как проверять изменения

```powershell
py -X utf8 tools/validate.py
py -X utf8 tools/build_pdf.py
.\serve.ps1
```

Проверки, которые уже ловили проблемы:

- **Сценарий занимает 5 листов** (3 до 02.08.2026, 4 после — наполнили подсказками
  ведущему; 5 с 12.08.2026 — добавились четыре пункта по итогам разбора аудиозаписи).
  Это плата за содержание, а не расползание вёрстки; лимит в `build_pdf.py` поднимался
  вместе с ним. Жёсткий лимит листов только у памятки. `break-inside: avoid` на блоке
  (`.blk`) раздувал документ ещё сильнее,
  потому что каждый блок уезжал на новую страницу. Разрыв запрещён только на уровне
  пункта (`.row`). Ужимать типографику дальше не стоит: документ читают во время
  разговора с водителем.
- **Памятка водителя обязана оставаться ОДНИМ листом** — её отдают на руки. Это
  единственное жёсткое ограничение по листам. 02.08.2026 при добавлении группы
  «Это видно в данных» она сорвалась на второй лист; вернули одним листом, ужав
  интервалы (`.cs`, `.grp`, `.qr-wrap`) и объединив две строки про CROSSCHEM.
  Кегль 9.5pt и размер QR 25 мм при этом не трогали — читаемость и сканируемость
  важнее. Если снова не влезает, резать контент, а не шрифт.
- **Как мерить переполнение памятки, не гадая.** `build_pdf.py` говорит только
  «два листа». Точную величину даёт замер в Playwright при ширине окна **703 px**
  (A4 минус поля 12 мм = 186 мм при 96 dpi) — на широком окне текст переносится
  иначе и высота обманчиво маленькая. Доступно `275 мм` (297 − поля 11 мм сверху
  и снизу). 12.08.2026 при добавлении двух новых строк было 291 мм.
  **Сокращение слов внутри строки почти ничего не даёт** — 8 правок по 15–25 знаков
  дали 0 мм, потому что число перенесённых строк не изменилось. Реально помогает
  только слияние строк в одну (−4…5 мм за штуку). Так и вернули 270 мм.
- Русские склонения счётчиков (`plural()` — теперь в общем `assets/js/util.js`) — был баг «32 минут».
- **Статический `import` не наследует `?v=` от импортирующего модуля.** `app.js`
  подключается с версией, а его `import './store.js'` — нет, и правки store.js
  приезжали из кэша PWA. Поэтому `store.js` и `util.js` импортируются динамически:
  `await import('./store.js' + new URL(import.meta.url).search)`. Добавляя новый
  общий модуль, подключать так же, иначе он унаследует ту же дыру.
- **`overflow: hidden` на предке ломает `position: sticky` у потомка** — предок с любым
  overflow, отличным от `visible` (даже `hidden` без реального переполнения), становится
  для sticky-элемента границей стика; если сам предок не скроллится (высота `auto`,
  как `.block`), sticky-потомок просто не цепляется к прокрутке страницы. На этом
  ловился прилипающий `.block__head` 02.08.2026 — решение: убрать overflow с `.block`,
  скруглять углы точечно на `.block__head`/`.block__body`.
- **`styles.css` и `app.js` (и `print.css`/`print.js`) грузятся с `?v=` через JS**,
  не обычным `<link>`/`<script src>` — иначе владелец правит цвета/логику, пушит,
  а на телефоне (особенно установленном как PWA) ещё долго открывается старая
  версия из кэша. `data/briefing.json` эту же проблему решает через `?v=` в `fetch()`,
  02.08.2026 такая же схема добавлена и для CSS/JS. Если правишь эти файлы и правки
  не видны в браузере — сначала проверь через `curl`, что на GitHub Pages уже новая
  версия, прежде чем подозревать деплой.
- Отсутствие горизонтального скролла на 375 px. Таблицы обязаны скроллиться
  внутри `.tbl-wrap`, а не растягивать страницу.
- Прогресс и таймер переживают перезагрузку; «Сбросить» чистит и то, и другое,
  а долгое нажатие на таймер — только время.
- QR должны **декодироваться в печатном размере** (25 мм ≈ 95 px), а не просто рисоваться.
  Проверять `cv2.QRCodeDetector` по скриншоту, а не на глаз.
- **Что видит владелец, если сломает JSON.** Он правит файл в веб-редакторе GitHub,
  и самая вероятная ошибка — не сломанный синтаксис (его подсветит GitHub), а
  удалённый/переименованный ключ: JSON остаётся валидным, а страница падает.
  `checkShape()` в `app.js` ловит это и называет ключ по имени; `validate.py`
  проверяет то же самое до публикации. Проверять негативным тестом (сломать —
  посмотреть сообщение — вернуть), а не только «работает на правильных данных».
  **`guide` намеренно вне `checkShape()`**: без него инструктаж вести всё ещё можно,
  ронять из-за него всю страницу неправильно. Но до 12.08.2026 он исчезал молча —
  `renderGuide()` просто выходил по `return`, и пропажу заметил бы только коллега,
  которому нечего читать перед первым инструктажем. Теперь на месте карточки
  появляется объяснение, а сценарий продолжает работать. Тот же приём стоит
  применять к любому «необязательному» разделу: не падать, но и не молчать.
- **Число листов PDF считает `build_pdf.py`** и ругается при превышении.
  Памятка водителя обязана быть одним листом — её отдают на руки.
- **Кнопка «Печать / PDF» (`window.print()`) — не источник финального PDF.** Если в
  диалоге Chrome включены «Заголовки и нижние колонтитулы», браузер сам допечатывает
  URL страницы и дату поверх контента — это настройка печати, CSS её не контролирует.
  Раздавать нужно `dist/*.pdf` от `build_pdf.py` (там колонтитула нет по умолчанию).

## Правило двух телефонов (02.08.2026)

У водителя их два, и это определяет половину блока 1:

- **Рабочий** (закреплён за тягачом, уезжает вместе с машиной): WhatsApp с офисом,
  SMSVinjetes, NESTE, CIRCLEK, закладка eurovignettes.eu — всё, чем платят за счёт
  компании. Лимит интернета 20 GB, общий на личное и рабочее (шаг `instr-internet`
  в гиде базы знаний).
- **Личный**: «HEAD, HDLG Инструкции» — **обязательно**, это условие допуска.
  «HEAD, HDLG Заправки» — по желанию. Причина: рабочий телефон водитель сдаёт
  с машиной, а база знаний нужна ему и на пересменке, и при смене машины.

Правя блок 1 или памятку, не сползать обратно к «рабочему телефону» по умолчанию.

## Открытые хвосты

1. Правила «450 л + 100 л реф», «не более 200 л на въезде в Испанию» и запрет заправки
   в шести странах взяты с сайта «Заправки». Их контент правится в Google-таблице
   и мог измениться — перед первым проведением стоит сверить.
2. **Тайминг: план 30 минут, вживую вышло 40** (аудиозапись реального инструктажа,
   расшифрована 12.08.2026). Сценарий пересобран под 30, но сам замер после
   пересборки ещё не делался — прогнать вслух с секундомером. Где именно утекало
   время и на сколько — раздел гида «Почему выходит 40 минут и как удержать 30».
3. **Подтверждено аудиозаписью 12.08.2026** (раньше было «написано по здравому
   смыслу»): состав девяти карт — восемь топливных плюс банковская; датчики уровня
   топлива стоят на всех тягачах и прицепах, сверяется каждая транзакция.
   Тогда же владелец решил: «Инструкции» на личный телефон — **обязательное условие
   допуска** (вживую звучало мягче, «желательно»); контакты офиса **предустановлены**
   на рабочем телефоне, вручную их больше не заводим.
   Остаётся неподтверждённым: что делать, если инспектор намекает на взятку сам
   (`red-bribe`). Номер разблокировки Universal (+371 26556503) записан **по роли**
   («руководитель отдела учёта»), а не по имени — чтобы фраза не ломалась у коллеги.
4. **Памятка держится впритык к одному листу** (жёсткий лимит, см. «Как проверять
   изменения» выше) — планируя новую строку, сначала прогнать `build_pdf.py` и
   посмотреть счётчик страниц, не полагаться на глаз.
